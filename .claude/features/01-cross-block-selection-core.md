## Scope

- In scope:
  - 롱프레스로 크로스 블록 선택 진입 (블록별 체크박스/별도 "선택 모드"
    토글 없음)
  - 같은 블록 안에서의 드래그는 iOS 네이티브 텍스트 선택을 그대로 사용
    (A2, 커스텀 로직 불필요)
  - 드래그가 블록 경계를 넘어가면 커스텀 크로스 블록 선택 로직으로
    전환(A3) — 여러 `ParagraphTextField`(`UITextView`)에 걸친 하나의
    선택 상태를 좌표 기반으로 추적. 착수 전 `closestPosition(to:)`
    기반 접근이 실제로 동작하는지 작은 스파이크로 먼저 검증한다(NO-010
    §4가 명시적으로 요구하는 절차) — 이 브리프의 구현은 이 검증
    결과를 전제로 진행한다.
  - 선택 범위 정규화: 시작점보다 위로 드래그해도 문서 순서 기준으로
    시작/끝이 재배정된다(A4, 불변조건 1)
  - 자동 스크롤: 드래그 지점이 화면 위/아래 가장자리에 닿으면 자동
    스크롤되고, 스크롤 중에도 선택 범위가 계속 연장된다(A5)
  - 선택 취소 조건(A6): 다른 블록 탭 → 그 위치로 포커스 이동 + 선택
    해제(a) / 키보드 "내리기" 버튼 탭 → 선택 유지, 키보드만 내려감(b)
    / 그 외 화면 요소 탭 → 선택 취소(c)
  - 편집 모드와 선택 모드는 동시에 성립하지 않는다(불변조건 2) — 크로스
    블록 선택이 시작되면 편집 모드 해제
  - 선택 하이라이트/드래그 핸들 시각 요소를
    `iOS_Editor_MultiBlockSelection` 디자인과 일치시킨다
- Out of scope / deferred:
  - 복사/붙여넣기 실제 동작(→ 03/04 브리프)
  - 외부 텍스트 붙여넣기(→ 05 브리프)
  - 선택 구간에 Bold/Italic 서식 적용(`tasks/NO-011.md` 소유)
  - 드래그 앤 드롭으로 블록 재배치 — 영구 스코프 밖(세션 메모리
    `project_block_editor_no_drag_reorder`)
  - A1(빈 커서 롱프레스 → "선택" 버튼으로 단어 선택)은 네이티브 iOS
    Edit Menu 동작이라 이 브리프에서 만들 것이 없음 — 단, 텍스트 선택
    메뉴의 "선택" 버튼 자체는 `tasks/NO-011.md`가 다루는 메뉴 컴포넌트
    범위와 겹치니 실제 착수 시 그쪽 진행 상황을 확인할 것

## Decisions & Deviations

- 크로스 블록 선택은 네이티브 `UITextView` 선택 API를 쓰지 않는
  완전히 커스텀 오버레이다 — `ParagraphTextField.swift`(블록당 1개
  `UITextView`)는 그대로 두고, 그 위에 별도 좌표 기반 하이라이트/핸들
  레이어를 얹는 방식으로 구현한다(NO-010 §4 "기술적 리스크" 참고,
  노션도 동일 문제를 자체 구현).
- "자손 블록 자동 포함 여부"는 이 방식에서 성립하지 않는 질문이라
  별도 로직을 만들지 않는다 — 드래그가 화면에서 지나간 범위가 곧
  선택 범위다(NO-010 §4에서 이미 폐기된 논의).

## Acceptance Criteria

- [ ] 블록 하나의 텍스트 중간에서 롱프레스하면 빈 커서만 놓이고
      단어 단위로 바로 선택되지 않는다(A1 — 네이티브 동작 확인용,
      구현 불필요하지만 회귀 없는지 확인)
- [ ] 같은 블록 안에서 드래그하면 iOS 네이티브 선택이 그대로
      동작한다(A2 — 커스텀 로직이 개입하지 않음을 확인)
- [ ] 드래그가 현재 블록의 위/아래 경계를 넘으면 네이티브 선택
      핸들/캐럿이 사라지고 커스텀 크로스 블록 선택 상태로 전환된다(A3)
- [ ] 시작점보다 문서상 앞으로 드래그하면 선택 범위의 시작/끝이 문서
      순서 기준으로 자동 정규화된다(A4, 불변조건 1)
- [ ] 드래그 지점이 화면 위/아래 가장자리에 닿으면 자동 스크롤되며,
      스크롤 중에도 선택 범위가 계속 연장된다(A5)
- [ ] 선택 도중 다른 블록을 탭하면 그 위치로 포커스가 옮겨가며 편집
      모드로 전환되고 기존 선택은 해제된다(A6-a)
- [ ] 선택 도중 키보드 툴바의 "키보드 내리기" 버튼을 탭해도 선택이
      유지된다(A6-b)
- [ ] 선택 도중 그 외 화면 요소(내비게이션 바 등)를 탭하면 선택이
      취소된다(A6-c)
- [ ] 편집 모드와 선택 모드가 동시에 성립하지 않는다(불변조건 2)
- [ ] 선택 하이라이트/드래그 핸들의 시각적 배치가
      `iOS_Editor_MultiBlockSelection` 디자인과 일치한다
