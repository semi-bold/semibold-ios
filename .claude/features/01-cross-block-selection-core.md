## Scope

- In scope:
  - 롱프레스로 선택 진입 (블록별 체크박스/별도 "선택 모드" 토글 없음)
  - **모든 드래그 선택은 블록 안/블록 경계를 넘는지 여부와 무관하게
    하나의 커스텀 선택 로직으로 처리한다(결정됨, 2026-10-01)** — iOS
    네이티브 `UITextView` 드래그-선택 동작에 의존하지 않는다(A2/A3,
    `CrossBlockSelection/README.md` 공통 불변조건 9). 여러
    `ParagraphTextField`(`UITextView`)에 걸친 하나의 선택 상태를 좌표
    기반으로 추적하며, 블록 경계를 넘는 순간에도 별도로 전환되는 로직
    없이 같은 추적 로직이 자연스럽게 이어진다. 착수 전
    `closestPosition(to:)` 기반 접근이 실제로 동작하는지 작은
    스파이크로 먼저 검증한다(NO-010 §4가 명시적으로 요구하는 절차) —
    이 브리프의 구현은 이 검증 결과를 전제로 진행한다. 타이핑을 위한
    캐럿 배치(길이 0인 커서 이동)는 이 범위에 포함되지 않는다 — 기존
    네이티브 편집 동작 그대로 유지한다(선택 "범위"를 만드는 행위만
    커스텀으로 통일하는 것).
  - 선택 범위 정규화: 시작점보다 위로 드래그해도 문서 순서 기준으로
    시작/끝이 재배정된다(A4, 불변조건 1)
  - 자동 스크롤: 드래그 지점이 화면 위/아래 가장자리에 닿으면 자동
    스크롤되고, 스크롤 중에도 선택 범위가 계속 연장된다(A5)
  - 선택 취소 조건(A6, 2026-10-02 결정으로 b/c 통합): 다른 블록 탭 →
    그 위치로 포커스 이동 + 선택 해제(a) / 그 외 모든 화면 요소
    탭(키보드 "내리기" 버튼 포함) → 선택 취소(b+c 통합) — 키보드
    내리기 버튼을 특별 취급해 선택을 유지시키는 예외를 두지 않는다
  - 편집 모드와 선택 모드는 동시에 성립하지 않는다(불변조건 2) — 크로스
    블록 선택이 시작되면 편집 모드 해제
  - 선택 하이라이트/드래그 핸들 시각 요소를
    `iOS_Editor_MultiBlockSelection` 디자인과 일치시킨다
- Out of scope / deferred:
  - 복사/붙여넣기 실제 동작(→ 03/04 브리프)
  - 외부 텍스트 붙여넣기(→ 05 브리프)
  - 선택 구간에 Bold/Italic 서식 적용(`tasks/NO-011.md` 소유)
  - 드래그 앤 드롭으로 블록 재배치 — 영구 스코프 밖(세션 메모리
    `project_block_editor_no_drag_reorder`)
  - A1(빈 커서 롱프레스 → "선택" 버튼으로 단어 선택)의 캐럿 배치
    자체는 네이티브 편집 동작 그대로라 이 브리프에서 만들 것이 없음.
    다만 그 뒤에 뜨는 메뉴는 `UIEditMenuInteraction`으로 통일하기로
    했으므로(`tasks/NO-011.md` §2.1), 더 이상 iOS가 자동으로
    띄워주지 않는다 — 메뉴를 수동으로 띄우는 트리거(롱프레스 제스처
    인식 등)는 `tasks/NO-011.md`가 다루는 메뉴 컴포넌트 범위이니 실제
    착수 시 그쪽 진행 상황을 확인할 것

## Decisions & Deviations

- **선택(드래그로 범위 지정)은 블록 안/크로스 블록 구분 없이 처음부터
  끝까지 완전히 커스텀 오버레이다** — `ParagraphTextField.swift`(블록당
  1개 `UITextView`)는 캐럿 배치/타이핑에만 네이티브 동작을 쓰고, 그
  위에 별도 좌표 기반 하이라이트/핸들 레이어를 얹어 선택 범위를
  추적·렌더링한다(NO-010 §4 "기술적 리스크"/"적용 범위 확장" 참고,
  노션도 비슷한 문제를 자체 구현). 애초에 "블록 안에서는 네이티브,
  경계를 넘으면 커스텀"으로 나누려 했으나, 두 구현을 계속 똑같아
  보이게 유지하는 비용이 더 크다고 판단해 하나로 통일했다 — 이 통일
  결정은 텍스트 선택 메뉴를 `UIEditMenuInteraction`으로 묶은 결정
  (`tasks/NO-011.md` §2.1)과도 맞물려 있다: 메뉴 노출 조건("선택
  범위가 비어있지 않다")이 선택 추적 메커니즘과 무관하게 하나로
  성립하려면, 추적 메커니즘 자체도 하나여야 한다.
- "자손 블록 자동 포함 여부"는 이 방식에서 성립하지 않는 질문이라
  별도 로직을 만들지 않는다 — 드래그가 화면에서 지나간 범위가 곧
  선택 범위다(NO-010 §4에서 이미 폐기된 논의).

## Acceptance Criteria

- [ ] 블록 하나의 텍스트 중간에서 롱프레스하면 빈 커서만 놓이고
      단어 단위로 바로 선택되지 않는다(A1 — 네이티브 동작 확인용,
      구현 불필요하지만 회귀 없는지 확인)
- [ ] 같은 블록 안에서 드래그해도 커스텀 선택 로직이 동작한다 —
      네이티브 드래그-선택에 의존하지 않는다(A2)
- [ ] 드래그가 현재 블록의 위/아래 경계를 넘어도 별도로 전환되는
      로직 없이 같은 커스텀 선택 로직이 이어지며, 선택 범위가
      여러 블록에 걸친 상태로 자연스럽게 확장된다(A3)
- [ ] 시작점보다 문서상 앞으로 드래그하면 선택 범위의 시작/끝이 문서
      순서 기준으로 자동 정규화된다(A4, 불변조건 1)
- [ ] 드래그 지점이 화면 위/아래 가장자리에 닿으면 자동 스크롤되며,
      스크롤 중에도 선택 범위가 계속 연장된다(A5)
- [ ] 선택 도중 다른 블록을 탭하면 그 위치로 포커스가 옮겨가며 편집
      모드로 전환되고 기존 선택은 해제된다(A6-a)
- [ ] 선택 도중 그 외 화면 요소(키보드 툴바의 "키보드 내리기" 버튼,
      내비게이션 바 등 포함)를 탭하면 선택이 취소된다(A6-b/c 통합,
      2026-10-02 결정)
- [ ] 편집 모드와 선택 모드가 동시에 성립하지 않는다(불변조건 2)
- [ ] 선택 하이라이트/드래그 핸들의 시각적 배치가
      `iOS_Editor_MultiBlockSelection` 디자인과 일치한다
